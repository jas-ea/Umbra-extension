# 02 - Use Cases and Screenshots

These screenshots use live public websites with the local Umbra extension loaded. They are not fixture pages.

## 1. Dense Documentation

![Umbra on Chrome Developers permissions docs](../assets/screenshots/chrome-developers-permissions.png)

Source page: https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions

Use case: a developer is reading an API or permissions page with left navigation, right-page anchors, top navigation, and inline code terms.

Value: Umbra keeps the article readable without hiding the navigation or changing the docs page.

## 2. Long Reference Article

![Umbra on Wikipedia Cassini-Huygens article](../assets/screenshots/wikipedia-cassini.png)

Source page: https://en.wikipedia.org/wiki/Cassini%E2%80%93Huygens

Use case: a reader is moving through a long reference page with a contents rail, infobox, article tabs, and appearance controls.

Value: Umbra keeps the current article block visually steady while the surrounding page context stays available.

## 3. Developer Triage

![Umbra on OpenAI Cookbook GitHub issues](../assets/screenshots/github-openai-cookbook-issues.png)

Source page: https://github.com/openai/openai-cookbook/issues

Use case: a developer is scanning an issue list with repository navigation, filters, labels, counters, and action buttons.

Value: Umbra can make one row or list region easier to hold in attention without removing the rest of the triage context.

## 4. Question Lists

![Umbra on Stack Overflow questions](../assets/screenshots/stackoverflow-questions.png)

Source page: https://stackoverflow.com/questions

Use case: a developer is reading a question summary on a page with side navigation, search, filters, right-rail cards, tags, and repeated rows.

Value: Umbra makes the selected question stand out while keeping sorting, filters, and surrounding questions usable.

## Notes For Public Use

These screenshots are useful for internal review and for showing real use cases. Before using them in paid ads or long-running public campaign assets, review third-party site branding and content rights. For launch posts, prefer screenshots that show the product behavior clearly and avoid unnecessary page text.
